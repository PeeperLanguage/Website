Every error on this page comes from the compiler itself, running in this page on
a small program.

## Reading an error

<Terminal run="auto">

```peeper
fn pick(flag: bool) -> i32 {
    let value: i32;
    if flag {
        value = 1;
    }
    return value;
}

fn main() {
    println(pick(true));
}
```

</Terminal>

- **The first line** gives the code and what is wrong.
- **`-->`** gives the file, line and column.
- **The labels** under the code point at each place that matters. Here they
  show where `value` was declared and where it is read.
- **`= note:`** explains the rule, and **`= help:`** suggests a change.

## The code's letter

The letter says which part of the compiler found the problem:

| Letter | Found while |
| --- | --- |
| `L` | reading the characters of the file |
| `P` | parsing the code into a tree |
| `M` | resolving modules and imports |
| `T` | checking types, paths, moves and borrows |
| `W` | looking for likely mistakes: a warning, not an error |

## Fixes

Some errors carry a fix, marked `= fix:`, with the changed line under it and
the new text highlighted. `peeper fix` applies these fixes to your files, and
an editor offers them as quick fixes.

<Terminal run="auto">

```peeper
fn main() {
    let total = 1 + 2
    println(total);
}
```

</Terminal>

<Terminal run="auto">

```peeper
fn main() {
    let n = 1;
    let r = &n;
    let m: i32 = r;
    println(m);
}
```

</Terminal>

```terminal title="peeper fix"
fixed src/main.peep:4:19: add `.*` to use the value it points to
```

A `= help:` line is only a suggestion, and `peeper fix` leaves it to you. A
guess at a mistyped name is one:

<Terminal run="auto">

```peeper
fn main() {
    let total = 3;
    println("total:", totla);
}
```

</Terminal>

## More errors

A function that can end without returning its value:

<Terminal run="auto">

```peeper
fn sign(n: i32) -> i32 {
    if n > 0 {
        return 1;
    }
}

fn main() {
    println(sign(1));
}
```

</Terminal>
